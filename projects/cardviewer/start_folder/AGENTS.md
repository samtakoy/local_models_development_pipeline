# Правила проекта для агентов

## Окружение
- Окружение и зависимости проекта — через uv. Зависимости описаны в pyproject.toml.
- Создать окружение и поставить зависимости: `uv sync`.
- Добавить зависимость: `uv add <пакет>`, зависимость для разработки: `uv add --dev <пакет>`.
- Команды проекта запускаются через uv: `uv run pytest`, `uv run python -m <модуль>`.
- Системный python и pip не использовать.

## Архитектура
- Код проекта — в папке src/.
- Простая, понятная, расширяемая архитектура.
- Единый источник правды (SSOT): каждое знание и каждая настройка определены в одном месте.
- Одна ответственность (Single Responsibility): у модуля и класса одна задача.
- Логика приложения отделена от веб-слоя и от хранения данных.

## Документация
- Архитектура общими блоками описана в README.md: модули и их ответственность, как запустить, как проверить.
- Кто меняет код, обновляет README.md, если изменились архитектура, запуск или проверка.

## Тесты
- Тесты — pytest, в папке tests/.
- Новый код покрывается тестами. Тесты проверяют конкретные значения, а не только отсутствие ошибок.
- Запуск: `uv run pytest`.
- Логику веб-слоя тесты проверяют через тестовый клиент фреймворка.
- Когда для проверки нужен запущенный сервер (тест запуска, проверка в браузере), приложение
  стартует командой из README на свободном порту.
- Есть тест запуска: приложение стартует командой из README и работает; веб-приложение
  отвечает на главной странице.

## Данные
- В src/ — только код, файлы данных туда не кладутся.
- Примеры и документы лежат в docs/: их не копировать, ссылаться на них по пути.
- Данные для тестов — в tests/data/. Файлы, которые тест создаёт, — во временной папке pytest (tmp_path).
- Данные, которые приложение создаёт при работе, — в папке data/ (папку добавить в .gitignore).
  Пути по умолчанию указывают в data/.

## Наблюдаемость
- Используем Production подход.
- По логам должно быть понятно, что делало приложение и почему произошла ошибка, без повторного запуска.
- Логи — стандартный logging, в консоль и в файл, например logs/app.log (папку с логами добавить в .gitignore).
- Логируются запуск с настройками, входящие запросы, ключевые сценарии (важные моменты), изменения данных и ошибки с трассировкой - все необходимое и важное.
- При отладке и разборе проблем сначала читать логи. Расширять логи по мере того как становится понятно что они важны.
- Не логировать чувствительные данные (security).
- Ошибки не глушить: исключение перехватывается, только чтобы его обработать; в остальных случаях
  оно логируется с трассировкой и передаётся дальше.
- Ошибка веб-запроса возвращается с кодом ошибки (4xx или 5xx), а не с кодом 200.

## Запуск приложения
- Порт по умолчанию — 8050.
- Порт может быть занят другой программой: чужие процессы не останавливать, взять другой порт.
