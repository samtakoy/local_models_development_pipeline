# Проект

Итоговая работа по курсу OTUS: LLM-инженер

> Мультиагентная система: конвейер разработки на локальных моделях

## Зачем такое надо

- Проверить возможности локальных моделей для кодинга
- Приватность при разработке с помощью LLM

## Что сделано

Пайплайн из агентов на Langgraph + Ollama. 

`PM` -> `исследователь кода` -> `архитектор` -> `сеньор (планировщик этапа)` -> `кодер` -> `ревьювер` -> `приемщик`

- Приложение при запуске смотрит на `set.toml` с заданием на разработку и указанием папки для разработки.
- В папку проекта предварительно можно закинуть папку docs с документацией и спецификациями, 
  а также файл AGENTS.md с инструкциями для агентов по конкретному проекту (загружается в начало контекста агента).

Если в проекте инициализирован git то перед стартом он должен находиться в чистом закомиченном состоянии,
иначе пайплайн не запустится. Если git отсутствует то он будет проинициализирован при запуске пайплайна
и будет сделан первый комит.

git - одно из необходимых условий работы пайплайна - через него система делает откаты в случае 
несанкционированных правок агентами.

├── projects/             задачи: set.toml и начальная папка проекта

├── runs/                 журналы и статистика прогонов

## Предупреждение о рисках использования

Агенты непредсказуемы (особенно слабые локальные модели), без контроля возможно:
- создание, редактирование, удаление файлов и папок на компьютере
- хаотическое убийство процессов в системе
- все что угодно

Не раз наблюдал, как локальная модель, преследуя свою цель, забывала обо всём на свете
и перебирала все возможные варианты доступных хаков, чтобы получить желаемое.
(создание файлов в случайном месте, удаление папки проекта, убийство процессов системы - все это было)

### Песочница

На macOS используется — sandbox-exec, а при запуске в докере Linux — Landlock (но не старые версии).

Вне этих двух сред - песочницы не будет.

Что ограничивает песочница:
- разрешает писать только в папку проекта, временную папку системы и некоторые кеши, которые 
  используют программы типа uv (нужно агентам для установки библиотек)
- чтение песочница не ограничивает: файловые инструменты агентов читают только папку проекта, а команды bash —
  всё, что доступно пользователю (в Docker — только содержимое контейнера)

**Важно**
Наличие песочницы - необходимое условие стабильной работы агентов, т.к. с помощью нее
также ограничиваются права ролей агентов (например, у ревьювера отбирают права менять файлы проекта)

Также предусмотрен механизм изоляции процессов до которых могут дотянуться агенты.
Агенты имеют возможность повлиять только на те процессы, которые стартовали они сами (macOS + докер).

Т.о. при запуске например на Windows без докера, да еще на слабых моделях:
- вы получите непредвиденные риски изменения в системе;
- из-за потери ограничения на изменение файлов проекта отдельными агентами пайплайн не будет работать корректно.

В macOS или Docker защита есть, но гарантий отсутствия ошибок не дается.

## Рекомендации по моделям

- qwen3.6:35b-a3b-coding-nvfp4 — проверенный вариант: доводит задачу среднего размера
  до почти рабочего приложения (прогон cardviewer — 11 часов). До 33 ГБ памяти.
- qwen3.5:9b — только для очень простых задач: на cardviewer приложение не заработало.
- VISION_MODEL — модель с поддержкой картинок; нужна для проверок вёрстки по скриншотам.
- AGENT_CTX_WINDOW — чем больше, тем лучше: агенты реже сбрасывают историю.
  35B поддерживает до 256к.


## Как пользоваться (запуск)

### Быстрый старт в Docker

Нужны: Docker (на Mac — Docker Desktop) и Ollama на этой же машине.

1. Клонировать репозиторий и перейти в папку `codeteam_v2`.
2. Скачать модель: `ollama pull qwen3.6:35b-a3b-coding-nvfp4` (в работе занимает до 33 ГБ памяти).
   Либо qwen3.5:9b - для очень простых задач (до 9 ГБ памяти).
3. Создать в папке `codeteam_v2` файл `.env`:

   ```
   OLLAMA_BASE_URL="http://127.0.0.1:11434"
   AGENT_MODEL=qwen3.6:35b-a3b-coding-nvfp4
   VISION_MODEL=qwen3.6:35b-a3b-coding-nvfp4
   AGENT_CTX_WINDOW=125000
   CODETEAM_RUNS_DIR="runs"
   CODETEAM_PROMPTS_DB_DIR="prompts_db"
   # необязательно: без ключа Context7 работает с меньшими лимитами
   # CONTEXT7_API_KEY=...
   ```

   В Docker адрес Ollama подставляется сам (`host.docker.internal`), `OLLAMA_BASE_URL` из `.env` нужен для запуска без Docker.

4. Запустить пример:

   ```bash
   ./run_docker.sh projects/docker_check_simple
   ```

**Что произойдёт:**
- соберётся образ codeteam: первый раз — несколько минут (Python, Node.js, Chromium), дальше — секунды;
- создастся папка проекта `workspaces/docker_check_simple` из `projects/docker_check_simple/start_folder` и в ней репозиторий git;
- агенты по очереди сделают приложение «Конвертер температур»: требования, план, код по этапам, ревью, проверки
  в браузере, приёмка. На qwen3.6 35B — около получаса;
- в конце результат скопируется из Docker в `workspaces/docker_check_simple`.

**Что показывает консоль:**
- шаги агентов: в квадратных скобках имя агента, затем номер шага и вызванные инструменты;
- итог каждого агента: шагов, запросов к модели, токены, время и путь к журналу;
- в конце — итог приёмки: задача принята или нет, и путь к отчёту.

Пути в консоли — пути внутри контейнера: `/app/runs/...` на машине — это `runs/...` в папке `codeteam_v2`.

**Где смотреть результат:**
- `workspaces/docker_check_simple` — готовый проект: код, тесты, README с командой запуска. Коммиты codeteam
  по этапам — в `git log`.
- `runs/<дата>-<модель>/` — журналы прогона, видны сразу, ещё во время работы:
  - `NN_<роль>_rN.md` — журнал агента: размышления, вызовы инструментов и их результаты;
  - `acceptance_report.md` — вердикт приёмки и что доработать;
  - `stats_report.md` — время, токены, инструменты по агентам и ролям.
- Файлы проекта во время прогона: Docker Desktop → Containers → `codeteam_v2-codeteam-run-…` → Files →
  `/app/workspaces/docker_check_simple`.

**Во время прогона не трогать:**
- `workspaces/<проект>` — в конце прогона папка перезаписывается результатом из Docker, правки пропадут;
- `run_docker.sh` и `docker-compose.yml` — оболочка читает скрипт по ходу работы.

У каждого проекта свой том в Docker: `codeteam_project_<папка проекта>_<отпечаток пути>`. Два прогона одного
проекта одновременно запускать нельзя. Список томов — `docker volume ls`, удалить ненужный — `docker volume rm <имя>`.

Остановить прогон — `Ctrl+C`: результат всё равно скопируется в `workspaces/<проект>`.

### Запуск без Docker (macOS)

Нужны: uv, Ollama, Node.js с `npx` (серверы Playwright MCP и Context7 MCP) и Google Chrome.

1. Установить зависимости: `uv sync`.
2. Создать `.env`, как в быстром старте; `OLLAMA_BASE_URL` — адрес Ollama на этой машине.
3. Запустить пример:

   ```bash
   uv run python -m codeteam.app.cli.main projects/docker_check_simple
   ```

### Примеры и свои задачи

Задача — папка в `projects/`:
- `set.toml` — задание и состав ролей; `project` — имя папки проекта в `workspaces/` или полный путь;
  в разделе `[pipeline]` обязательны `browser_check` (проверки в браузере), `library_docs` (советник
  по документации) и `roles` (список ролей); образец — `projects/docker_check_simple/set.toml`;
- `start_folder/` — начальное содержимое проекта (например `AGENTS.md`, документы): копируется в папку проекта,
  если её нет или она пустая.

Примеры: `docker_check_simple` (конвертер температур), `docker_check` (он же, с требованиями к внешнему виду),
`cardviewer` (просмотр обучающих карточек, долгий прогон).

Папку рабочих проектов можно сменить переменной `CODETEAM_WORKSPACES_DIR` в `.env`, по умолчанию — `workspaces`.

### Продолжение прерванного прогона

После каждой законченной роли codeteam пишет снимок `runs/<прогон>/<журнал роли>.state.json`. С него прогон
продолжается с роли, которая шла следующей. Роль, на которой прервали, снимка не имеет и начнётся заново.

Если прошлый запуск не скопировал результат на Mac (закрыли терминал, выключился компьютер), сначала забрать его
из тома проекта:

```bash
./run_docker.sh projects/<задача> --pull
```

1. Найти последний снимок:

   ```bash
   ls runs/<прогон>/*.state.json | tail -1
   ```

2. Убрать недоделанное прерванной роли: с незакоммиченными правками в проекте codeteam продолжать откажется.

   ```bash
   cd workspaces/<проект>
   git status
   git reset --hard && git clean -fd
   cd -
   ```

   Недоделанная работа прерванной роли удаляется безвозвратно — роль сделает её заново. Личные папки агентов
   `.ct-work/` остаются: они в `.gitignore`.

3. Запустить с флагом `--resume`:

   ```bash
   ./run_docker.sh projects/<задача> --resume runs/<прогон>/<NN_роль>.state.json
   ```

Журналы продолжения пишутся в новую папку прогона.

Продолжать тем же способом, каким запускали: в снимке записаны пути внутри контейнера (`/app/workspaces/...`),
поэтому прогон из Docker продолжается только через `run_docker.sh`.
