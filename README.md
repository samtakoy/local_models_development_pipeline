## Финальная проверка в браузере (веб-тестировщик)

После последнего этапа веб-тестировщик запускает приложение и проходит требования заказчика в браузере
через Playwright MCP. Пишет отчёт и вердикт. Итоговый вердикт по отчётам тестировщиков выносит роль `acceptance`:
если задача не принята, команда делает этап исправлений по её плану доработки, и проверка повторяется;
число кругов ограничено (`FIX_ROUND_LIMIT` в `core/roles/acceptance/node.py`).
Входит в список ролей по умолчанию.

Список ролей задаётся в файле состава проекта `set.toml`; без веб-тестировщика:

```toml
[pipeline]
browser_check = true
library_docs = true
roles = ["pm", "researcher", "architect", "architect_review", "senior", "developer", "developer_review"]
```

`browser_check` обязателен: `true` — перед первой ролью проверяется, что браузер открывается, и приёмщик этапа может проверять приложение в браузере; `false` — браузер не используется, роли `web_tester` в `roles` быть не должно.

`library_docs` обязателен: `true` — перед первой ролью проверяется, что запускается Context7 MCP, и разработчик может спрашивать советника по документации библиотек; `false` — советника нет.

Что нужно на компьютере:
- Node.js с `npx`: Playwright MCP скачивается и запускается командой `npx @playwright/mcp@0.0.83`;
- доступ в интернет для советника разработчика по документации: Context7 MCP запускается командой `npx @upstash/context7-mcp@4.1.1`;
- Google Chrome.

Пакеты npm для Playwright MCP и Context7 MCP скачиваются в свой кэш — папку `.npm-cache` рядом с файлом `.env`, общий кэш npm (`~/.npm`) не используется.

Окно браузера задаётся в `.env`: `BROWSER_HEADLESS=true` — без окна, `false` — с окном (удобно для отладки).

Ключ Context7 задаётся в `.env`: `CONTEXT7_API_KEY=ctx7sk-…`; без ключа советник работает с меньшими лимитами.
`CONTEXT7_CHECK_KEY_AT_START=true` — при прогреве Context7 MCP ключ проверяется пробным поиском библиотеки.

## Продолжение прогона со снимка

После каждой роли рядом с её журналом пишется снимок: `runs/<прогон>/<журнал роли>.state.json` —
коммит проекта и состояние пайплайна. С любого снимка прогон продолжается с роли, которая шла после этой:

```
uv run python -m codeteam.app.cli.main projects/cardviewer --resume runs/<прогон>/18_stage_40_senior_r1.state.json
```

Продолжение пишет журналы в новую папку прогона, личные папки `.ct-work` проекта не переносит в архив.
В проекте не должно быть незакоммиченных правок, иначе запуск откажется.

## Отчёт статистики прогона

В конце прогона в его папку пишется отчёт `runs/<прогон>/stats_report.md`, он собирается из файлов `*.stats.json`.
Пересобрать отчёт, например для старого прогона:

```
uv run python scripts/run_stats.py runs/<прогон>
```
